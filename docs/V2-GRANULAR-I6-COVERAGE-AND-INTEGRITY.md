Static AST evidence covers all 37 literal top-level state keys read/written by the current gateway and game modules; ten additional simulation roots have explicit proposed owners. Seed evidence: `_default_campaign_seed` in `runtime/v2_campaign_gateway.py`; dynamic evidence: `game_content.py`, `game_npcs.py`, `game_npc_knowledge.py`, `game_adventure.py`, `game_source_map.py`, `v2_npc_cognition.py`, `v2_authoring_services.py` and native contracts. Unknown/custom fields BLOCK migration until mapped; no inferred conversion or silent omission.

## Operational integrity policy implemented in I6

1. **Format preflight:** read-only `mode=ro`, query_only, foreign keys, one consistent SQLite transaction. Inspect persisted metadata, exact known profile/module/source pins/snapshot/legacy hash and fence definitions. Never trust client labels, AI output, extension or filename for selection. Reads include committed WAL (no immutable=1). Existing unknown/empty/corrupt files refuse startup; nonexistent paths keep native fresh legacy bootstrap. No schema repair.
2. **Normal legacy startup:** new launcher and gateway check before authoring/auth/Save writer opens, then preserve native R1 recovery. Recheck before later authority opens. The first genuinely new legacy bootstrap is explicitly distinguished because authoring tables are created before CampaignStore. No granular binding/table is allowed on the normal writable gateway.
3. **Prepared inspection:** capabilities say NOT_FULLY_AUDITED and playable=false. A routine NPC read checks selected source records against authenticated paths, exact source pins and session/Save ownership; result says BOUNDED_PATH_CHECKED. DM memories max twenty; player/observer/preview never receive private memory/provenance. Untouched corruption may remain undiscovered until full audit. This provisional inspection never grants write authority.
4. **Independent full audit:** explicit DM-only read-only audit reuses the entire I5 source/cache/event/receipt/ledger proof algorithm with record_verification=false. The default I5 function behavior is unchanged. Report FULL_AUDIT_COMPLETE only for the exact snapshot returned after successful completion; never set a durable verified flag or change g_i5_audits from this facade. A concurrent newer head is not verified by an older report.
5. **Material actions/reopen/checkpoint:** no new material path. Existing I5 fixture writes still require their own genesis/reopen full audits, bounded dependency checks, revision-age gate and pre-checkpoint full verification. A read-only inspection audit cannot refresh their write eligibility. Normal R1 recovery/replay and FULL durability remain untouched.
6. **Crash/deferred verification:** every reader reopens a consistent read snapshot and reauthenticates; format checks do not recover or commit pending work. No background verifier or active-format promotion is installed. A future background audit must be bound to its exact Save/head and hold activation until complete; it may not declare the current world verified merely because an earlier snapshot passed. Full audits cost tens of seconds and remain explicit work, not hidden inside a routine projection.
7. **Application states:** frontend checks have a five-second capability timeout, explicit errors and a retry control. Prepared/unavailable states disable campaign mutation controls and explain read-only/unavailable status. Old endpoint absence (HTTP 404 only) is labelled NOT_REPORTED/native legacy fallback; auth, network, corrupt or server failures never grant granular capability. No migration/activation button exists.
