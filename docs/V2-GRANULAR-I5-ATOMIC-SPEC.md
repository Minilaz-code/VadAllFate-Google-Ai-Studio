## Authority configuration and authentication

Only disposable_fixture.create accepts a NEW exclusive i5-disposable-*.sqlite path. Existing paths fail before SQLite opens them. Normal startup never imports/selects the route or installs its SQL. The returned ticket is required to reopen its own fixture: filename, marker and nonce are verified READ-ONLY before opening a CampaignStore writer, followed by mandatory full integrity validation. A cookie/type/private-object gate prevents accidental activation; it is not a Python sandbox against hostile code already running with host/file access.

All campaign bindings remain PREPARED. No ACTIVE format, production registration, frontend endpoint or runtime gateway dispatch is added. Existing authority legacy admission/dispatch/staging/recovery/disposition/commit methods gain only a no-op-by-default guard, fencing granular fixture campaigns on explicitly configured fixture stores. Their remaining AST bodies are identical to baseline. Fresh-fixture SQL also fences legacy INSERT/UPDATE/DELETE of the campaign_state sentinel. This is not an old-executable launcher or a promise of zero operational writes by arbitrary old binaries: complete old-format negotiation/launcher policy remains I6/I8.

FixtureSession is an unforgeable-in-practice random server credential: only its hash is in the fixture session table, compared in constant time. The worker frame carries session_ref, never the secret. The actual host supplies the authenticated capability separately. Session identity, enabled status, DM role, principal, actor, campaign, Save and NPC scope are independently checked. Capabilities are fixture-only, not a replacement for real application authentication. Player/NPC capabilities cannot author material mutations.

The fixture module uses frozen 0.3.0 StateModuleManifest, StateModuleAccessProfile and StateModuleRegistration shapes, verified against the existing locked schema registry. It declares mechanics_authority NONE, direct_canonical_write=false, COMMIT_AUTHORITY_ONLY slices, exact driver/schema refs and two capabilities. The registration lives only in the fresh fixture's closed descriptor, not the production registry. Missing/changed manifests, versions, driver scope, source pins or enabled mount fail closed.

The descriptor binds canonical world-minute units and CAMPAIGN_ZERO epoch, clock ID campaign_id + '.world-minute.v1', I2/I3/I4 profile versions and supported operations. Its hash is in the canonical head and the I4 dependency configuration ref. The existing normative SnapshotRef is projected WITHOUT field changes: save_id=logical Save ID, state_revision=global revision, world_time.tick=decimal world-minute string and snapshot_hash=explicit I4 Snapshot HashRef; runtime_integration_profile_hash binds the exact fixture descriptor. No legacy tick conversion or hash equivalence is assumed. This first slice reads/retains world time and does not implement clock-advance/scheduler actions.

## Independent candidate and human approval

Supported material request is exactly TWO ordered intents: npc.memory.record then relationship.adjust. NPC identities are immutable source-pinned records instantiated through trusted authority-owned new-fixture genesis; dynamic NPC creation/edits are not claimed. Actor identity is a read-only fixture reference, not a general character/combat implementation. Its new I5 actor hash is explicitly distinct from the historical unverified I2 actor placeholder; no old actor data is opened or converted.

The existing I3 worker ValidationResult remains only structural evidence. Before any material write, the I5 validator independently checks authenticated lineage, mounted module, current Save-bound snapshot, clock/pin/source identity, NPC and actor authenticated leaves, absent memory ID, actual relationship endpoints, I2 revision/hash AND I4 target hash, bounded deltas and coherent causal ownership.

Only private, unverified TOLD/TOLD memories are supported. Memory summary must equal the approved input statement; actor must be the authenticated character; target must be the approved NPC and relationship; source_ref must be I5.authorised-tell.v1; minute must equal current canonical minute. Book references, old/made-up events, WITNESSED claims, fact promotion, arbitrary fields/SQL and unsupported mechanics fail. Trust/affinity use the existing supported +/-0.2 delta cap/clamping, familiarity +0.05 and preserved other values.

At DM-authorised admission the COMPLETE prepared candidate (including selected consequence, note and scripted result evidence) is pinned in g_i5_admission_approvals with the session ID, fingerprint and exact bytes. This fixture mode explicitly approves a fully prepared candidate; it is not an autonomous AI approval workflow. A first worker completion cannot change even an otherwise valid bounded delta/note/result. Independent state validation is repeated at staging/commit; a claimed PASS or a copied approval reference alone is never sufficient. Pending work can retrieve the exact approved input after restart before staging, without generating anything new.

NPC/private memory projection is server-side: DM may inspect in scope, NPC capability only its own allowed NPC, player receives public identity with no NPC memories. Responses are capped at twenty memories ordered by authoritative event revision. General party disclosure, beliefs, knowledge admission, cognition, notes, quests, inventory, factions, routines, spatial state and combat are not covered. No AI is called here; retained replies are explicitly ORIGINAL_SCRIPT_NOT_AI.

## One material SQLite transaction

CommitAuthority.granular_fixture('commit', ...) performs one existing-writer BEGIN IMMEDIATE and either one COMMIT or one rollback. The closed helpers receive that transaction connection. Order is:

1. Decode/size/coherence checks, authenticate session, check exact DM approval, admission bytes/status/Save/nonce, explicit codec, dispatch token and pending head. Existing exact receipt resolves a retry before any consequence; conflicting bytes fail.
2. Independently validate the COMPLETE two-record candidate and compute planned exact native/I4 rows and validation hash. Load only dependency records and authenticated paths/siblings, not the world document. Full audit age is checked.
3. Insert one real existing RuntimeEvent and evidence-chain row. This event is the authoritative DM-approved tell, with actor, observer, minute, statement, unverified category, admitted input, approved full-frame fingerprint, result hash, relationship note and planned row hashes. Event ID is derived from campaign/Save/action/nonce/next revision; it is not chosen by a model.
4. I2 connection-bound driver inserts memory and CAS-updates relationship/history. The material event already exists in this SAME uncommitted transaction for I2 witness checks. Update only the two records' canonical predecessor metadata. Compare actual rows with the independently planned rows.
5. Maintain only affected authenticated cache paths, then CAS the canonical head once. Two row changes yield one global revision, one snapshot, one material event and one authoritative receipt.
6. Persist original validated intents in applied_patches, causal_ledger, outbox, determinism_proofs, idempotency_receipts and APPLIED admission disposition. COMMIT once, acknowledge afterward.

No external model/TTS/network call occurs under the writer. Failure after event/each entity/cache/before or after head/ledger/outbox/receipt/before COMMIT rolls everything back. Failure immediately AFTER COMMIT retains all effects and resolves using the exact prior receipt; no second memory, delta or event is applied. Actual os._exit process-death tests cover a partial typed write and the lost-response window.

## Event/root/receipt cycle avoidance and full verification

Native RuntimeEvent identity, revision, action/causation, type and COMPLETE payload are hashed into the I4 chain projection's result_hash; the projection also binds sequence/actor/minute/affected IDs. No native event data is silently dropped. The relationship-evidence table is checked as an exact projection of the immutable event note/IDs/sequence. Ordered native event-chain hashes, all records and source/config/module dependencies are independently rebuilt on full audit.

The DAG is approved input/results -> planned row hashes -> independent validation hash and full event core -> evidence prefix + content root -> Save snapshot -> receipt/ledger/proof/outbox. The validation hash binds the approved request fingerprint and event ID, not the future event/snapshot hash. Events never contain resulting snapshot/receipt/ledger hashes. Operational outbox retries/claims are excluded; its immutable payload must still match the actual event.

Full audit verifies typed/I2 hashes, every I4 source leaf and derived cache, event chain/cardinality/time, relationship-note projection, retained approved and staged bytes/fingerprints, applied intents, event/outbox/ledger/receipt/independent proof consistency, and the complete genesis-to-current snapshot/revision receipt chain. It does not merely compare a cached root string.

## Fresh-only additive schema and audit policy

Existing CampaignStore startup and frozen schemas are unchanged. The explicit fixture installer executes versioned entity_core_v1.sql plus authority_core_v1.sql statement-by-statement IN the authority transaction; no executescript implicit commit and no production migration dispatcher.

New-fixture additions: input_admissions.result_codec_ref/logical_save_id; derived entity-root/evidence-count/snapshot fields on g_campaign_heads; g_i5_fixture/mounts/sessions/record_meta/actors/nodes/event_chain/audits/genesis/recovery_audit/admission_approvals; guarded legacy sentinel triggers and one causal-memory index. See the exact SQL asset for columns, keys and FKs. g_campaign_heads plus g_campaign_bindings remain the sole current world/Save head. campaign_state is a fixed non-world FK sentinel, never a rewritten campaign document. g_i5_record_meta adds only predecessor metadata; g_i5_nodes is derived; bounded genesis/request/receipt/evidence JSON is immutable history, not another current-state authority.

The complete approved frame and staged frame are retained separately as bounded immutable authority evidence (up to two copies per action). This has linear history cost and is measured; it does not embed expanding campaign state and is not a JSON paging scheme. No memories/events/inputs are deleted to satisfy limits.

Existing R1 commit-request IDs are globally unique. A fresh-fixture unique index reserves each full approved request ID at admission, and triggers reject already committed IDs and conflicting legacy ledger inserts. Reservation and admission roll back together. Reusing an ID in another campaign is rejected before it can poison that campaign queue; entity/action/nonce IDs remain campaign-scoped. A stale disposition retains its request-ID reservation as evidence.

Initial safe fixture policy: full source/cache/evidence audit at genesis and every reopen; explicit full audit before checkpoint; normal actions verify necessary record/path dependencies only. After 100 committed revisions without a full audit, new work is rejected until explicit verification. No silent repair/rebuild-to-accept or history trimming. Corruption of an untouched row may be discovered only at a full audit: there is no constant-time whole-file verification claim. Checkpoint is maintenance through the same authority connection outside a material transaction; it audits all fixture campaigns, keeps WAL/synchronous FULL/FKs ON, then truncates WAL. Benchmarks disable auto-checkpoint ONLY in their disposable files to measure actual before/after WAL frames.

Existing I2 driver/SQL, I3 codec/contracts, I4 hash module/goldens, old request DTOs, legacy codec/hash function and normative 0.1/0.3 schemas retain their meanings. One I2 static test is necessarily updated: its pre-I5 blanket ban on all granular references becomes a ban on module-level/startup imports, allowing only the explicitly approved guarded sole-authority method. Driver lifecycle and normal-route denial assertions remain. Existing legacy authority function ASTs are identical after removing the added no-op-by-default fixture guards.
